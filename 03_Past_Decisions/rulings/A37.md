# A37 — Opening a model whose file and journal don't match: the newest file on disk is the mode...

Status: Active | Subject: Files, saving and undo | Principles: G09 | Date: 2026-11-22
Replaces / replaced by: Refines A32 (replaces its 'journal newer than the file' trigger)
Where in the code: Not built: T101

Opening a model whose file and journal don't match: the newest file on disk is the model, and an older version is never put back over a newer file. If that file is the new file of a save of ours that stopped part way (it matches the .saving journal, or its ShopSketchRev is the journal's + 1 with a whole new pair), the save is finished. Otherwise, a file that doesn't match our journal was written by someone else (FreeCAD, even when it carries an older revision number): it opens as an outside edit with its undo floor (A25). The .prev pair is used only when the main file is missing or unreadable. File dates only decide 'never go back to something older'; the contents decide the rest.

Why: Your call, 2026-11-22: FreeCAD saves the revision it opened, so a FreeCAD save made while Shop Sketch was closed carries an older number but is the newest work; the old rule put our .prev back over it (found in H063).
